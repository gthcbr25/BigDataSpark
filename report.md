# Отчёт по лабораторной работе №2

**Тема:** ETL-пайплайн на Apache Spark, модель «звезда» в PostgreSQL и витрины в ClickHouse.
**Автор:** Скрипачёв Ф. М., группа М8О-409Б-23.

## Цель работы

Реализовать средствами Apache Spark ETL-пайплайн: перенести исходные CSV-данные
в PostgreSQL, построить из них аналитическую модель «звезда», а затем сформировать
шесть аналитических витрин в ClickHouse.

## Использованные компоненты

Все сервисы поднимаются одним `docker-compose.yml`:

- **PostgreSQL 16** — хранит сырую таблицу `mock_data` и модель «звезда»;
- **Apache Spark 3.5.1** — master и worker, выполняют ETL;
- **ClickHouse 24.8** — хранит витрины (база `marts`).

Связь Spark с PostgreSQL и ClickHouse — через JDBC-драйверы из каталога `jars/`.

## Ход выполнения

1. **Загрузка сырых данных.** При старте PostgreSQL выполняет `init/01_load_raw.sql`:
   все 10 CSV командой `COPY` попадают в таблицу `mock_data` (10000 строк).

2. **Построение звезды (`spark/build_star.py`).** Spark читает `mock_data` через
   JDBC, очищает значения, приводит числа и даты к нужным типам и формирует шесть
   измерений (`dim_customer`, `dim_seller`, `dim_product`, `dim_store`,
   `dim_supplier`, `dim_pet`) и таблицу фактов `fact_sales`. Суррогатные ключи
   присваиваются оконной функцией `row_number`, дубли устраняются по natural key
   (`md5` от нормализованных полей). Готовые таблицы записываются обратно в
   PostgreSQL, дополнительно создаются проверочные представления.

3. **Построение витрин (`spark/clickhouse_reports.py`).** Spark читает таблицы
   звезды из PostgreSQL, считает агрегаты и записывает шесть витрин в ClickHouse.
   DDL таблиц отправляется в ClickHouse по HTTP, данные — через JDBC. Каждая
   витрина закрывает соответствующий пункт задания:
   - продажи по товарам, клиентам, времени, магазинам, поставщикам;
   - качество продукции с расчётом корреляции между рейтингом и объёмом продаж.

## Проверка результата

Модель «звезда» в PostgreSQL (представление `view_load_quality`):

| Показатель | Значение |
|---|---:|
| Строк в `mock_data` | 10000 |
| Строк в `fact_sales` | 10000 |
| Потерянных строк | 0 |
| Фактов без связи с измерениями | 0 |

Витрины в ClickHouse (число строк):

| Витрина | Строк |
|---|---:|
| `report_product_sales` | 10000 |
| `report_customer_sales` | 10000 |
| `report_time_sales` | 12 |
| `report_store_sales` | 10000 |
| `report_supplier_sales` | 10000 |
| `report_product_quality` | 10000 |

Витрина `report_time_sales` содержит 12 строк — по числу месяцев за 2021 год.
Остальные витрины детализированы до отдельных товаров, клиентов, магазинов и
поставщиков. Пример проверки топ-10 товаров и помесячной выручки выполнялся
запросами `clickhouse-client` к базе `marts`.

## Вывод

Реализован полный ETL-пайплайн на Apache Spark. Данные без потерь прошли путь
от сырых CSV до модели «звезда» в PostgreSQL и далее до шести аналитических
витрин в ClickHouse. Все проверки подтвердили корректность: 10000 строк перенесены
в таблицу фактов, связи с измерениями заполнены полностью, витрины сформированы
и доступны для аналитических запросов средствами ClickHouse.
